# SUN-1000 Checkpoint 1N-A / 1N-A2 — v2 Deterministic Chaos Matrix

Machine-readable-enough index of every scenario in
`apps/edge-api/tests/chaos-v2.test.ts` (general v2 lifecycle faults, checkpoint
1N-A) and `apps/edge-api/tests/chaos-v2-settlement-recovery.test.ts`
(settlement_pending durability / post-settlement uncertainty / reconciliation /
restart recovery, checkpoint 1N-A2's completion of the gap 1N-A left open),
executed together by `pnpm security:chaos` (`scripts/security/run-chaos.ts`).
Every scenario is a named, deterministic `it()` block — no random fault
probabilities. `run-chaos.ts` fails closed unless every row below both ran and
passed, not merely that the overall process exited 0.

Target: the forward v2 service family exclusively (`company_evidence_graph.v2`,
`web_context_verified.v2`, `document_evidence_json.v2`,
`verify_agent_output.v2`) and their real `/v2/...` HTTP routes. Credential-free
throughout: every fault is injected at the `PaymentEvidenceProvider`/executor
seam `paid-services.ts` already exposes — zero Nevermined calls, zero CDP calls,
zero live settlements.

### Checkpoint 1N-A2 — settlement/recovery completion

These 5 scenarios close the gap 1N-A left open: they call
`createX402ServiceRoute` directly with `rail: 'nevermined'` and a real `.v2`
`serviceId` (`company_evidence_graph.v2`) — proving the **shared**
`x402-service.ts`/`D1PaymentAttemptRepository` settlement_pending/
reconciliation/restart-recovery implementation (gated by `rail`, never by
`service_id` — confirmed by direct inspection) is genuinely correct for a v2
identity. This deliberately does **not** go through `paid-services.ts`'s live
`/v2/...` wiring, which remains permanently CDP-only per checkpoint 1M's
disclosed, accepted Phase-1 design (`v2CdpRoute()`) — that wiring is untouched
by this file. Once Phase 2 mounts a real v2 Nevermined route through that same
wiring, it inherits these exact, now-proven guarantees automatically.
