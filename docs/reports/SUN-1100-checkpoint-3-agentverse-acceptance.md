## Second correction to the Agentverse path

Checkpoint 2 predicted the Agentverse "External Agent + A2A Protocol" UI flow
would require only an account login, no API key, based on the generic official
A2A onboarding docs. The actual live UI the user reached ("Add your agent
details" → Agent Name / Agent Endpoint URL → keywords → generated integration
script) instead produced a **Python script** using
`uagents_core.utils.registration.register_chat_agent`, requiring **two**
credentials:

- `AGENTVERSE_KEY` — an Agentverse account API key
- `AGENT_SEED_PHRASE` — a self-generated, high-entropy secret the user creates
  (not issued by Agentverse), used to deterministically derive the agent's
  uAgents/Almanac cryptographic identity

This is the third distinct set of Agentverse instructions encountered across
this task (checkpoint 1: assumed `AGENTVERSE_KEY` only; checkpoint 2: assumed no
key at all via a pure "External Agent" flow; checkpoint 3: the real, working
path needed both a key and a seed phrase). Recorded honestly rather than
silently reconciled — Agentverse's own onboarding surface appears to route
differently depending on choices made partway through the UI (e.g., "chat agent"
vs. a generic external agent), and only the path actually exercised end-to-end
is authoritative.

1. User filled the Agentverse UI form: Agent Name `SITEBORNE Utility`
   (Agentverse's own auto-generated/truncated form of the name entered), Agent
   Endpoint URL `https://utility.siteborne.net/a2a` (the real
   `supportedInterfaces[0].url` from the live Agent Card — not guessed).
2. Agentverse generated a Python registration script using `uagents-core`'s
   `register_chat_agent`.
3. This session prepared the venv/dependency setup (`python3 -m venv`,
   `pip install uagents-core`) and saved the exact script Agentverse provided,
   unmodified, to a local scratch path (`/tmp/agentverse-register/`, outside the
   repository).
4. **Neither credential was ever seen, generated, or handled by this session.**
   `AGENTVERSE_KEY` was retrieved by the user from their own Agentverse account
   dashboard. `AGENT_SEED_PHRASE` was generated by the user, in their own
   terminal, via a command this session suggested
   (`python3 -c "import secrets; print(secrets.token_hex(32))"`) but did not
   itself execute — the generated value never appeared in this conversation.
5. The user ran the script themselves, in their own terminal, with both secrets
   set as local environment variables. Output (shared back, contains no secret
   values): `successfully registered to Agentverse` /
   `successfully set agent to active`.
6. **Read-after-write verification**, performed by this session, real HTTP calls
   only:

   - `GET https://agentverse.ai/v1/search/agents/agent1qv8f9...` — confirms
     `name: "SITEBORNE Utility"`, `status: "active"`, `type: "uagent"`,
     `AgentChatProtocol 0.3.0` registered.
   - The free-text search index (`search_text: "siteborne"`) had not yet caught

     indexing lag, not a registration failure; the record itself is real, live,
